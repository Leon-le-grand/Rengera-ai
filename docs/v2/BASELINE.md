## 3. Authentication, sessions and roles

- Session tokens are HMAC-SHA256 signed base64url payloads in two HTTP-only cookies: `rengera_admin_session` and `rengera_user_session` (`web/lib/auth.ts:31-34`, `web/lib/auth.ts:187-192`).
- Cookies are `httpOnly`, `secure` in production, `sameSite: 'lax'`, path `/`, with an 8-hour maximum age (`web/lib/auth.ts:247-265`, `web/lib/auth.ts:34`).
- `AUTH_SECRET` must be at least 32 bytes. In production a missing/default secret throws inside `getAuthSecret`; request paths use `tryGetAuthSecret` so sessions become unavailable instead of crashing the page (`web/lib/auth.ts:43-89`, `web/app/page.tsx:9-17`).
- Passwords use scrypt with N=32768, r=8, p=1, a 16-byte salt, a 64-byte derived key and a `scrypt$cost$r$p$salt$hash` encoding (`web/lib/auth.ts:35-39`, `web/lib/auth.ts:91-183`).
- The roles are `admin`, `staff` and `user` (`web/lib/auth.ts:6`). `admin` is issued only for the environment-configured administrator email; citizen `app_users` rows may carry `staff` or `admin` (`web/app/auth-actions.ts:109-129`, `web/app/auth-actions.ts:158-163`).
- `getAdminSession()` requires a valid admin cookie and a case-insensitive match with `ADMIN_EMAIL` (`web/lib/auth.ts:320-341`). The admin session is mapped into the citizen account slot with `id: null` (`web/lib/auth.ts:400-428`).
- Migration 007 creates `app_users` with `role in ('user','staff','admin')`, `status in ('active','suspended')`, a case-insensitive email index, RLS enabled and **no policies**; only the service role can read it (`web/supabase/migrations/007_create_app_users.sql:9-41`). Sign-in checks `status === 'active'` (`web/app/auth-actions.ts:149-151`).

**Observed session limitations.** After a cookie is issued, `getUserSession()` decodes the signed claims and does not query `app_users`; the comment claiming it is "Always re-validated against Supabase" is not matched by the implementation (`web/lib/auth.ts:366-398`). A suspended or deleted account therefore keeps access until the 8-hour cookie expires; `getAdminSession()` is also cookie-only after issuance. There is no server-side session store or revocation list in the current app. `staff` has no distinct permission path: the only workspace gate is `adminUser?.role === 'admin'` (`web/components/app/AppDashboard.tsx:46-47`), and `staff` receives only a label (`web/components/app/AppDashboard.tsx:111`, `web/components/app/AppDashboard.tsx:178`).

## 6. Retrieval, safety and citation behavior

**Order of operations in the citizen answer** (`web/app/actions.ts:332-536`):

1. Deterministic emergency detection runs before retrieval or model calls. A keyword match returns the urgent response immediately (`web/app/actions.ts:341-345`, `web/lib/safety.ts:64-115`).
2. Help and small-talk guards return fixed localized replies without retrieval or model calls (`web/app/actions.ts:352-368`).
3. If Supabase is configured, `retrieveSupabaseLegalContext(query, 8)` calls the public `search_legal_context` RPC (`web/app/actions.ts:372-384`, `web/lib/supabase-retrieval.ts:112-127`).
4. If no source was retrieved and there is no open-article context, the action returns a localized fallback instead of calling the model (`web/app/actions.ts:448-459`).
5. The model receives the retrieved context plus at most six trimmed history turns; article questions receive the focused four-section prompt (`web/app/actions.ts:461-504`).
6. `verifyCitations` checks article numbers, law references and URLs against retrieved source rows and discards the answer if more than 30% of citation-shaped tokens do not resolve (`web/app/actions.ts:255-330`, `web/app/actions.ts:523-535`).

**Retrieval details.** `search_legal_context` searches article-level rows and falls back to whole-law rows only when the law has no article rows (`web/supabase/migrations/015_fix_retrieval_and_status.sql:53-107`). It excludes `status = 'repealed'`, returns full article `content`, caps results at 10 and exposes `status` (`web/supabase/migrations/015_fix_retrieval_and_status.sql:69-76`, `web/supabase/migrations/015_fix_retrieval_and_status.sql:101-107`). The client trims each excerpt to 1,400 characters and the whole context to 14,000 characters (`web/lib/supabase-retrieval.ts:44-54`). Citation sources exclude the preamble and collapse duplicate law/article pairs (`web/lib/supabase-retrieval.ts:82-109`).

**Safety details.** Emergency patterns are hard-coded English, Kinyarwanda and French substrings with word-boundary matching for single words (`web/lib/safety.ts:13-23`, `web/lib/safety.ts:64-74`). The urgent reply uses fixed official contacts 112 (Police), 166 (RIB) and 3029 (Isange) and does not cite a law (`web/lib/safety.ts:97-113`, `web/lib/safety.ts:117-153`). The USSD route never calls the model and sends the same three contacts on menu option 3 (`web/app/api/ussd/route.ts:13-19`, `web/app/api/ussd/route.ts:187-191`).

**Known retrieval/citation gaps:**

- `verifyCitations` returns `discard: false` immediately when `sources.length === 0`, so an article-context answer can be shown without any citation verification (`web/app/actions.ts:262-265`). The article text itself comes from the client (`web/app/actions.ts:142-152`, `web/app/actions.ts:465`).
- The verifier checks token presence, not article-to-law pairing or whether the cited text supports the claim; the 30% threshold and caveat are the only safeguards (`web/app/actions.ts:267-329`).
- The comment says unresolved citations are "removed", but the implementation only appends a caveat (`web/app/actions.ts:323-327`).
- Search substitutes the RLRC homepage `https://www.rlrc.gov.rw/` when `source_url` is null (`web/supabase/migrations/015_fix_retrieval_and_status.sql:66`, `web/supabase/migrations/015_fix_retrieval_and_status.sql:88-90`). That makes a missing direct source look like a source.
- Retrieval formatting prints `status || 'active'` when status is null (`web/lib/supabase-retrieval.ts:71`), and several row casts coerce any unknown status to `active` (`web/app/legal-actions.ts:557-559`, `web/app/legal-actions.ts:598-600`). Unknown legal force is therefore presented as active.
- A search failure is caught and replaced with the literal context "Legal search is temporarily unavailable." but the action can still proceed if an article context exists; the product does not distinguish "search outage" from "no sources" in the model prompt (`web/app/actions.ts:385-388`).

## 11. Baseline conclusions for migration

1. Preserve `web/` as the runnable legacy baseline until each V2 slice passes parity and authorization checks; do not delete its routes, actions or migrations during the rebuild.
2. Port the deterministic emergency, no-source and small-talk guards before or with the answer API; they already work without a model (`web/app/actions.ts:341-368`, `web/lib/safety.ts:64-115`).
3. Treat the current citation verifier as a partial guard, not a source of truth; V2 must verify article/version pairing and claim support and must verify article-context answers (`docs/v2/ARCHITECTURE_REVIEW.md:13`).
4. Fix the owner-scoping and service-role write paths listed in section 9 before exposing equivalent V2 endpoints (`docs/v2/05-API-AUTH-AND-RBAC.md:11-13`).
5. Keep SQL migrations under `web/supabase/migrations/` until a recorded ownership move; hosted application remains separately gated (`docs/v2/RESEARCH.md:180`, `AGENTS.md:27`).
